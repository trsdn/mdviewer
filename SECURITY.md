# Security Policy

## Supported versions

The project actively supports the latest released version and the current `main` branch. Older releases are considered legacy and may not receive fixes unless a specific need is identified.

## Reporting a vulnerability

Please do not open a public issue or discuss a vulnerability in a public pull request.

Use one of the following private reporting paths:

- GitHub private vulnerability reporting: https://github.com/trsdn/mdviewer/security/advisories/new
- If GitHub private reporting is not possible, contact the maintainer privately via the repository owner contact channel and include a minimal reproduction and affected version

When reporting, please include:

- a brief description of the vulnerability
- affected version(s) and environment
- steps to reproduce the issue
- expected outcome versus actual behavior
- any relevant logs or screenshots, sanitized to remove secrets or personal data

## What to expect after a report

We aim to acknowledge reports within five business days. We will then work privately to assess, reproduce, and fix the issue where appropriate. We may ask for additional details, verification, or a minimal reproducer while the report is being triaged.

## Disclosure and safe handling

Please do not disclose reported issues publicly before a fix has been agreed. Do not include credentials, tokens, secrets, or personal information in test logs or issue text. If a fix is created, the maintainer will coordinate the appropriate disclosure timing and update release notes as needed.

## Contact

For private follow-up, use the GitHub Security Advisory form linked above or the repository maintainer contact channel. Do not report security issues through public support channels.
